# Tsumugi 設計メモ

言葉を紡ぐ、ローカル LLM 内蔵の日本語入力メソッド (macOS)。

## 1. 誰の、どんな困りごとを解くか

**想定する人**: 毎日 Mac で日本語を大量に書く人。メール、チャット、ドキュメント、コードのコメント。

観察される困りごと (共感 → 問題定義):

| 場面 | 困りごと | 本当に欲しいもの |
|---|---|---|
| 同音異義語 (こうせい・こうえん) | 文脈を見ればわかるのに、毎回スペースを連打して選ぶ | 文脈を読んで最初から正しい字が出る |
| 定型の言い回し (お世話になっております) | 何百回も同じ文を全部打つ | 打ち始めたら続きを出してくれる |
| 自分だけの語彙・人名 | 一度直しても次にまた間違える | 一度直したら二度と間違えない |
| 新しい IME への不安 | 打った内容がどこかへ送られていないか | 端末の外に一切出ないと言い切れる |

**問い**: どうすれば「考える速さで書ける」状態を、入力内容を端末の外に出さずに作れるか。

## 2. 体験の原則

1. **手を止めさせない** — 打鍵から表示まで体感ゼロ。LLM の結果を待って表示が遅れることがあってはならない。
2. **ちらつかせない** — 目の前の文字が理由なく変わると不安になる。LLM の見直しは「最初からその結果で出す」。
3. **提案は控えめに、採用は 1 キーで** — 先読みは確信があるときだけ出す。採用は Tab、無視はそのまま打ち続けるだけ。
4. **一度教えたら忘れない** — 自分で選び直した変換は、LLM より辞書より優先する。
5. **端末の外に出さない** — 変換も学習もすべてローカル。学習は止められ、消せる。
6. **慣れた操作を壊さない** — Space・Enter・矢印・F6〜F10 は既存の日本語入力と同じ意味。

## 3. 操作の流れ

```
未入力 ──打鍵──▶ 入力中 (ライブ変換) ──Space/矢印──▶ 候補選択
  ▲                │  Enter: 確定                    │ Enter: 確定 (選び直しを学習)
  │                │  Tab:   先読みを確定             │ Esc:   入力中へ戻る
  └────────────────┴─────────────────────────────────┘
確定の直後: よく続けて入力する句があれば先読みを表示 (Tab で確定)
```

| キー | 入力中 | 候補選択中 |
|---|---|---|
| 文字 | 打ったそばから漢字に変わる | いまの変換を確定して次の入力へ |
| Tab | 先読みを確定 | 次の候補 |
| Space / ↓ | 候補を開いて次の候補へ | 次の候補 |
| Shift+Space / ↑ | — | 前の候補 |
| ← → | 文節を選ぶ | 文節を移動 |
| Shift+← → | 文節を縮める / 伸ばす | 同じ |
| 1〜9 | (数字を入力) | その番号の候補を選ぶ |
| Enter | 確定 | 確定 |
| Esc | 先読みを消す → もう一度で入力を取り消す | 入力中へ戻る |
| F6 / F7 / F10 (Ctrl+J / K / L) | ひらがな / カタカナ / 英数 | 同じ |
| 英数 / かな | 直接入力と日本語入力の切り替え | — |

先読みピルの左のアイコンで出どころがわかる: 時計 = 自分の履歴、きらめき = LLM の予測。

## 4. 構成

```
┌──────────────── TsumugiIME (InputMethodKit) / TsumugiPlayground ────────────────┐
│  キーイベント → KeyMapping → Session.handle(key) → SessionView → 未確定文字列 + パネル │
└───────────────────────────────────┬───────────────────────────────────────────┘
                    TsumugiCore (純 Swift・UI 非依存)
   Composer ─ ローマ字 → かな
   Converter ─ ラティス + Viterbi、後ろ向き A* の N-best、LLM 出力の検証 (match)
   SystemDictionary ─ Mozc OSS 辞書を独自バイナリ化して mmap (約 129 万語 / 63MB)
   UserModel ─ 選び直した変換・確定した句・句のつながりを学習 (JSON 1 ファイル)
   Session ─ 状態機械。辞書の結果を即表示し、LLM を締め切りつきで待つ
                    TsumugiLLM
   ZenzModel ─ zenz-v3.2-small (GPT-2 系 約 9 千万パラメタ, 74MB) を llama.cpp で実行
```

### 変換は「辞書が土台、LLM が見直し、ユーザーが最終決定」

1. **辞書 (同期, 1〜10ms)**: 読みからラティスを作り、単語コスト + 接続コストの最小経路を Viterbi で求める。
2. **LLM (30ms の締め切りつき)**: 左文脈と読みを zenz に渡して変換させ、その出力が **ラティス上で読みと一致するか検証** してから採用する。
   LLM が読みと無関係な文字を作っても表示には出ない。辞書にない英字表記 (ChatGPT など) だけは対応づけを緩めて通す。
3. **ユーザー**: 自分で選び直した語が含まれる文節は、LLM の結果で上書きしない。

締め切りに間に合えば最初から LLM の結果を表示し (ちらつきなし)、間に合わなければ辞書の結果を出して後から差し替える。

### LLM を打鍵ごとに間に合わせる工夫

読みは 1 打鍵で 1 文字しか伸びないので、前回の出力の大半は今回も正しい。前回の出力を「当て推量」として
プロンプトに続けて **1 バッチで評価** し、モデルの選択と一致するところまでを一気に採用、食い違った位置からだけ生成し直す。
KV キャッシュの接頭辞再利用と合わせて、1 トークンずつ生成する場合の数分の一で済む。

### 先読み (Tab 補完) の出どころ

| 優先 | 出どころ | 条件 |
|---|---|---|
| 1 | 履歴: 打ちかけの読みで始まる、過去に確定した句 | 3 文字以上打った / 2 文字なら 2 回以上・1 文字なら 4 回以上使った句 |
| 2 | 履歴: 直前の確定のあとによく続く句 (確定直後) | 2 回以上、かつ半分以上の割合で続いている |
| 3 | LLM: zenz に読みの続きを予測させ、変換して表示 | トークンごとの確率 0.4 以上、積 0.2 以上、2 文字以上伸びる (確定直後は 0.45 以上) |

LLM の予測は句読点・確信のない文字の手前で止めるので、言い切れるところまでしか出ない。

### 学習

| 覚えるもの | きっかけ | 効き方 |
|---|---|---|
| 読み → 表記 | 候補を自分で選び直して確定 | ラティスに専用ノードとして参加。回数に応じて 3000〜7000 のコスト優遇 (60 日で半減) |
| 確定した句 | すべての確定 | 打ちかけからの補完 |
| 句のつながり | 30 秒以内に続けて確定 | 確定直後の先読み |

保存先は `~/Library/Application Support/Tsumugi/user_model.json` (パーミッション 600)。入力メニューから一時停止と全消去ができる。
パスワード欄では macOS がセキュア入力に切り替えるため、入力メソッド自体が呼ばれない。

## 5. 検討して選んだこと

| 論点 | 選択 | 理由 |
|---|---|---|
| 変換コア | 自作 (辞書データのみ Mozc OSS) | 仕組みを自分のものにでき、LLM・学習との組み合わせ方を自由に決められる。コアは Session の裏にあり差し替え可能 |
| LLM | 変換特化の zenz 1 本 | 実測で変換 10〜30ms、続きの予測も同じモデルでできた。汎用 LLM (0.5B〜) は 8GB の Mac で常駐させるには重く、今回は不要と判断 |
| 推論 | CPU (性能コア 4 スレッド) | このサイズでは GPU より立ち上がりが速く安定 (GPU は初回 400ms 超) |
| LLM の出力の扱い | ラティスで検証してから採用 | 小さなモデルの作り話を画面に出さない |
| 先読みの見せ方 | カーソル下の小さなピル | 他アプリの文字の上に薄い文字を重ねることは入力メソッドからはできない。位置が動かず視線を奪わない |
| 文末での自動確定 | しない | 確定後は直せないため、確定は必ず利用者の操作で |
| 未入力時の数字・記号 | そのままアプリへ渡す | 「2026」のたびに Enter を押させない |

## 6. 実測 (M3 / 8GB)

| 項目 | 値 |
|---|---|
| 辞書変換 (10〜17 文字、上位 5 件) | 3〜9ms (初回のみ 36ms) |
| LLM 変換 (打鍵ごと、当て推量つき) | 7〜30ms |
| 1 打鍵あたりの処理 (LLM の変換 + 先読みを同期実行した最悪値) | 25〜65ms。実際は 30ms で表示し、残りは裏で続行 |
| 常駐メモリ (起動直後) | 約 83MB |
| アプリ全体 | 141MB (辞書 63MB + モデル 74MB) |

## 7. いまの限界と次の一手

- 数字・日付・単位・顔文字などの特殊変換は未実装 (辞書にある範囲のみ)。
- 入力中のカーソル移動による途中編集はできない (文節単位の操作のみ)。
- 確定後の再変換、ユーザー辞書の手動登録 UI は未実装。
- 候補パネルはキーボード操作のみ (クリック不可)。
- 左文脈は自分が確定した文字列だけ。アプリ側の既存の文章は読んでいない。
- 学習データが増えたときの「文体に合わせた LLM の個人化」は、zenz v3 のプロフィール条件 (タグ U+EE03) を使えば拡張できる。
